# 青盾 2.0 可执行计划书 v2（12 天赶工版 · 修订版）

> **本版基于《青盾 2.0 可执行计划书（12 天赶工版）》修订，诊断依据见 `qingdun-2.0-plan-review.md`。**
>
> **修订摘要（6 处关键改动）**
> 1. **D2 出临时告警集** → 消除 D2–D3 数据空窗，让 D3 切片按期可跑。
> 2. **D0 三项 Spike**（PDF 字体 / 公网选型 / 数据列探查）→ 可行性风险前置，不留在后面。

> 4. **契约单向派生链**（Pydantic → openapi → 自动生成 mock → CI 校验）→ 一次性消灭联调字段漂移。
> 5. **预聚合表 + keyset 分页前置** → D9 压测从"救火"变"预防"。
> 6. **减负三招 + 砍单清单 + 9 条"不许有"验收断言** → 把 40% 的负载缺口压到 10%。

## 3. 角色与协作规则（修订分工：削 B 峰）

| 角色 | 负责 |
|---|---|
| **A（大数据）** | 建库/ETL/视图/聚合表/部署/备份/工作台/交易流水/模型页/设置页/审计页/ML 打分+metrics/**SAR PDF 生成（服务端）**/**报告 v2**/数据侧脱敏 |
| **B（AI/全栈）** | 契约/Pydantic 模型/openapi/自动生成 mock/CI 校验/JWT/ML 接口接入/预警列表/详情/因子可视化/前端公共文件/app.css/table.css/components.css/契约回归/压测报告 |

**减负三招**（相对原版）：
1. PDF 生成 **B → A**（A 本就负责 PDF 数据侧；B 只提供下载端点与字体验证）。
2. 报告 v2 整体 **B → A**（与交易流水页共用列表/筛选/下载组件，A 有现成模式）。
3. 空态/错误态/窄屏 **B → A**（配套拆样式文件，避免公共文件冲突）。

**协作硬规则**
1. 所有 `feat` 从 `dev` 切，PR 回 `dev`，**合入 `dev` 才算交接**。
2. **分支寿命 ≤2 天，PR ≤10 个文件**，一个分支只做一件事。
3. **公共文件归 B**：`api.js`、`app.css`、`table.css`、`components.css`、`main.py`。A 不改公共文件；A 新增独立 `dashboard.css` / `transactions.css` / `reports.css`。
4. A 要加接口字段：**先发 Issue + 改 `api_contract.md` + 重生成 mock**，B 在合并窗口处理。**禁止页面先猜字段、后补契约。**
5. **公共文件合并窗口**：每天 **10:30 / 15:30** 各一次，B 统一合，A 不直接改。窗口外只接受阻塞级 hotfix（由 B 当天合）。
6. 每天 **09:15 站会 15 分钟**（只讲：昨天完成、今天计划、阻塞），**并同步写入 `docs/standup.md`**——不依赖口头同步（防一人缺席即失联）。
7. **阻塞超过 2 小时用 Mock/降级，不干等。**
8. 每日至少合一次 `dev`；合前跑冒烟（§4）；**`dev` 每天必须可运行、可演示**。
9. **契约冻结（D2）后新增接口 = L1 违约**，需 A、B 双人书面确认才可加。

**交接只交代三样**：① 文件具体路径；② 先打开哪个页面 / 跑哪条命令 / 连哪个库；③ 什么算通过（一个数字或一个动作）。

## 7. 数据与接口口径（全队统一）

### 7.1 数据口径

| 项 | 口径 |
|---|---|
| 交易总数 | 748,869 笔 |
| 字段 | 59 列，入库约 25 列（D0 探查后确认映射表） |
| 账户数 | 1,115 个 |
| 可疑交易 | 411 笔（0.055%）→ **仅存于 `eval_label`，不进 API** |
| 可疑账户 | 12 个 |
| case / 手法 | 12 个 case / 7 类 |
| 时间窗口 | 2024-01-01 ～ 2024-07-06，页面写「统计区间」，不写「今天」 |
| 告警队列 | top 3,000 + 规则命中，约 3–5k 条 |
| 每条告警因子 | **恰好 8 条** SHAP |
| 模型版本 | `xgb-v1` |
| 融合分 | `final_score = 0.3*rule + 0.7*model` |
| 处置状态 | 固定种子 85% 待处理 / 15% 已处置 |
| 处置记录来源 | 种子记录标 `actor='system_seed'` + 前端「系统预置样例」标签；审计记录写 `source='seed'` |
| 分页返回 | 统一 `{items,total,page,size}`，空数组不返回 null |
| CSV | `utf-8-sig`，服务端流式，**强制筛选条件** |
| PDF 字体 | `frontend/assets/fonts/NotoSansSC-Regular.ttf`（**TTF，非 OTF**；子集化 ≤2MB） |

### 7.2 模型口径（D4 产出基线，D5 钉死，D9/D11 复核）

| 项 | 约定 |
|---|---|
| 划分方式 | **按 case 留一交叉验证（12 折）** 为主 + 时间切分（01-01～05-31 训练 / 06 月验证 / 07-01～07-06 测试）为辅 |
| 主指标 | **case 级检出率**（12 类中检出几类） |
| 辅指标 | 交易级 precision / recall / F1 / AUC，**必须标注 n 值**（测试集约 41 正样本，需注明置信区间） |
| 负采样 | 若训练时负采样，**必须做校准还原**并把公式写进 `model_card.md` |
| 消融 | 提供「纯规则 / 纯模型 / 融合」三组 case 检出率对比，证明融合有增量 |
| 因子口径 | 因子解释对应**模型部分**（占融合分 70%），页面显式说明；因子含 `shap_value / contribution / direction / unit`，并给出「其他因素合计」使占比合计 100% |

### 7.3 接口契约变更流程

`Issue 说明字段/原因` → `改 api_contract.md` → `改 Pydantic 模型` → **重新生成 mock（禁止手改）** → `B 合并窗口改代码` → `A 页面跟进` → `契约回归通过`
**禁止页面先猜字段、后补契约。**

**契约单向派生链**（消灭字段漂移）：
```
Pydantic 模型 → openapi.json → mocks/*.json（自动生成）→ 前端 api.js 类型常量 → CI 契约校验（键集合比对）
```
